# CMS schema — the inventory sheet

Alki House's catalogue is maintained by the client in a Google Sheet. The site renders **one row
per product**; nothing about a product lives anywhere else. This document fixes the columns so the
design (built now) and the sync plugin (built later) agree.

**The site is in Spanish** (confirmed 2026-09-13), so every value the client types — names,
taglines, descriptions, spec labels, condition — is Spanish. Column keys stay as below; the sheet's
header row may show the Spanish label in brackets, and the plugin maps it.

The local stand-in for the sheet is
`workflows/04-design/.tmp/site-src/data/products.json`, generated by `data/build-catalogue.mjs`
from the client's stock ledger and layered with `data/catalogue-overrides.json` (hand-written
merchandising). Its columns are the sheet's columns.

## Columns

| Column | Type | Required | Rendered where | Notes |
| :--- | :--- | :--- | :--- | :--- |
| `id` (ID) | text, unique | yes | Nowhere visible | The stable key. Product images live under `assets/products/<id>/`, overrides are keyed by it, and **saved carts** hold it. Rows built from the ledger carry the English slug (`zhiyun-weebill-3`); a row the client adds gets `slugify(name)` on its first sync. Never edit it afterwards. |
| `slug` (URL) | text, unique | yes | URL `productos/<slug>.html` | Spanish, from the name, accents stripped (`jaula-sony-fx30`). Fixed on first sync; changing it breaks links and shared carts' product links. |
| `name` (Nombre) | text | yes | Everywhere, and in the WhatsApp order | Spanish, head noun first: "Jaula Sony FX30", "Batería Kastar LP-E17H". Model names stay as sold ("Zhiyun Weebill 3"). |
| `brand` (Marca) | text | no | Card meta, product page tag, brand filter | Blank for generics. Sony/Canon only when the item is an OEM part, not when it merely fits that camera. |
| `category` (Categoría) | enum | yes | Filters, rail, related, `?cat=` links | One of: `gimbals` (Gimbals y estabilizadores), `iluminacion` (Iluminación de estudio), `modificadores` (Softboxes y modificadores), `audio` (Audio), `monitores` (Monitores y grabación), `rigs` (Jaulas, rigs y soportes), `adaptadores` (Adaptadores y filtros), `energia` (Baterías y energía), `cuidado` (Cuidado y fundas), `camaras` (Cámaras y lentes), `accesorios` (Accesorios). |
| `price` (Precio) | number (the ledger's $) | no | Cards, stage, product page, cart, WhatsApp order | Blank renders **"Precio a consultar"**; the cart counts it apart and the order says so. |
| `stock` (Stock) | integer | yes | Status badge, in-stock filter, "N disponibles", cart cap | `0` renders **Agotado**, hides the add button and offers "Avisarme cuando llegue" on WhatsApp; the product stays listed. The cart never lets a quantity exceed it. |
| `condition` (Estado) | text | no | Product page, `Nuevo` badge | Text starting `Nuevo` ("Nuevo, sellado") triggers the Nuevo badge. Otherwise free text ("Seminuevo, grado A"). |
| `tagline` (Frase) | text | no | Stage, product hero | One sentence. |
| `description` (Descripción) | long text | no | Product page, El Detalle | Two to four sentences. Falls back to a generic line. |
| `specs` (Especificaciones) | list of `Etiqueta: valor` | no | Stage (first three), product page table | One per line in the sheet cell, e.g. `Carga: hasta 3.5 kg`. |
| `featured` (Destacado) | checkbox | no | Home page stage and floor ordering, catalogue sort | The first five featured with photos are on El Escenario. |
| `tags` (Etiquetas) | comma list | no | Search | Free words ("vlog", "entrevista"). Search also matches the English name and ignores accents. |
| `images` (Imágenes) | list of URLs or file names | no | Everywhere, cart thumbnails | Up to five. The first is the card, hero and cart shot; the second is the hover angle. Managed by the plugin, not typed by hand. |

Derived at build/sync time, not columns: `status` (`in-stock` / `sold-out`), `categoryLabel`,
and `nameEn` (ledger rows only: the English name the category rules and the image harvester run on).

Internal ledger columns (purchase cost, shipping, commissions, seller) are **never** synced. The
sheet the client maintains should be a separate tab or file from the accounting ledger.

## How the site consumes it

- **Build (now)**: `build-site.mjs` renders every row into `productos/<slug>.html` from the one
  product template, the catalogue grid, the home page stage/floor/kits, and embeds a slim JSON copy
  (`slug, name, brand, category, price, stock, featured, q`) into `productos.html` for client-side
  filtering.
- **Instatic (later)**: the sync plugin writes the same rows into an Instatic data collection and
  the product template becomes the collection's page template. The `22-instatic-api-sync` notes
  apply: `PATCH /admin/api/cms/data/rows/:id` replaces `cells` wholesale, and a publish republishes
  every page.

## The cart and the WhatsApp order

Every add button carries a snapshot of its row: `{id, slug, name, price, stock, img}`. The cart
(`sections/cart.js`) keeps those in the browser's `localStorage` under `alki-carrito-v1`, so a cart
survives a closed tab and is shared across tabs, and sends nothing anywhere until the customer
presses **Enviar pedido por WhatsApp** on `pedido.html`. The message is one numbered line per
product with quantity, unit price and line total, the estimated total, the customer's name,
delivery choice and note. It goes to the number in `site-src/data/site.json`.

Because the cart holds a snapshot, a price or stock change in the sheet reaches a saved cart only
when the customer adds that product again; the shop confirms the final price in the chat. That is
why the order says **Total estimado**.

## Sync plugin — what it has to do

1. Read the sheet (Sheets API, service account with read access to the one file).
2. Validate each row against the table above; reject a row with no name or no category and report it.
3. Upsert by `id`; never delete a row that disappeared from the sheet — mark it `stock 0` and log it.
4. Mirror `images`: download new URLs into Instatic media, keep existing ids.
5. Publish once at the end, not per row.
6. Run on a schedule (hourly) and on demand.
