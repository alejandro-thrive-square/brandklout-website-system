# CMS schema — the inventory sheet

Alki House's catalogue is maintained by the client in a Google Sheet. The site renders **one row
per product**; nothing about a product lives anywhere else. This document fixes the columns so the
design (built now) and the sync plugin (built later) agree.

The local stand-in for the sheet is
`workflows/04-design/.tmp/site-src/data/products.json`, generated by `data/build-catalogue.mjs`
from the client's stock ledger and layered with `data/catalogue-overrides.json` (hand-written
merchandising). Its columns are the sheet's columns.

## Columns

| Column | Type | Required | Rendered where | Notes |
| :--- | :--- | :--- | :--- | :--- |
| `slug` | text, unique | yes | URL `/products/<slug>` | Derived from the name on first sync; never changes afterwards or links break. |
| `name` | text | yes | Everywhere | English product name, brand first when there is one. |
| `brand` | text | no | Card meta, product page tag, brand filter | Blank for generics (a super clamp, a light stand). Sony/Canon only when the item is an OEM part, not when it merely fits that camera. |
| `category` | enum | yes | Filters, rail, related | One of: `gimbals`, `lighting`, `modifiers`, `audio`, `monitors`, `rigs`, `adapters`, `power`, `care`, `cameras`, `accessories`. |
| `price` | number (USD) | no | Cards, stage, product page | Blank renders **"Ask for price"**. |
| `stock` | integer | yes | Status badge, in-stock filter, "N on hand" | `0` renders **Sold out**; the product stays listed. |
| `condition` | text | no | Product page, `New` badge | `New, sealed` triggers the New badge. Otherwise free text ("Pre-owned, graded A"). |
| `tagline` | text | no | Stage, product hero | One sentence. |
| `description` | long text | no | Product page, The Detail | Two to four sentences. Falls back to a generic line. |
| `specs` | list of `Label: value` | no | Stage (first three), product page table | One per line in the sheet cell, e.g. `Payload: up to 3.5 kg`. |
| `featured` | checkbox | no | Home page stage and floor ordering, catalogue sort | The first five featured with photos are on The Stage. |
| `tags` | comma list | no | Search | Free words ("vlog", "interview"). |
| `images` | list of URLs or file names | no | Everywhere | Up to five. The first is the card and hero shot; the second is the hover angle. Managed by the plugin, not typed by hand. |

Derived at build/sync time, not columns: `status` (`in-stock` / `sold-out`), `categoryLabel`.

Internal ledger columns (purchase cost, shipping, commissions, seller) are **never** synced. The
sheet the client maintains should be a separate tab or file from the accounting ledger.

## How the site consumes it

- **Build (now)**: `build-site.mjs` renders every row into `products/<slug>.html` from the one
  product template, the catalogue grid, the home page stage/floor/kits, and embeds a slim JSON copy
  (`slug, name, brand, category, price, stock, featured`) into `products.html` for client-side
  filtering.
- **Instatic (later)**: the sync plugin writes the same rows into an Instatic data collection and
  the product template becomes the collection's page template. The `22-instatic-api-sync` notes
  apply: `PATCH /admin/api/cms/data/rows/:id` replaces `cells` wholesale, and a publish republishes
  every page.

## Sync plugin — what it has to do

1. Read the sheet (Sheets API, service account with read access to the one file).
2. Validate each row against the table above; reject a row with no name or no category and report it.
3. Upsert by `slug`; never delete a row that disappeared from the sheet — mark it `stock 0` and log it.
4. Mirror `images`: download new URLs into Instatic media, keep existing ids.
5. Publish once at the end, not per row.
6. Run on a schedule (hourly) and on demand.
