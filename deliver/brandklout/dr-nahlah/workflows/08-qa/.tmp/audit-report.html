Published site · encorercm.com 77 URLs measured 20 August 2026

Every page of the site, driven by a browser

The site had passed every gate this project owns. It had also been serving 72 dead before/after sliders, no alt text on any image, and a JavaScript error on 44 of its 77 URLs. Each gate reads a different layer of the build; none of them had ever loaded the page a visitor actually gets. This audit does, at desktop and at phone width, and everything below was found and closed in that pass.

What was wrong

Six defects, every one of them site-wide rather than confined to a page. Five are closed and live; the sixth is a platform limit with a stop-gap in place.

Fixed8 pages · 72 sliders

The before/after sliders were held shut by a dead CSS rule

Instatic's importer rewrites <input type=range> to type="text". An earlier session answered that by hiding the stray box and making the whole figure a drag surface, in a script called before-after.js. That script was retired once site.js took over and started coercing the input back to a range — but its CSS stayed behind, and .pk-ba input {display:none !important} hides the very element site.js repairs.

It survived because it lived in runtime-states.css, the one stylesheet on the site with no local copy anyone diffed. That file now has a local owner and the simulator loads it.

Fixedall 77 URLs · 614 images

Every image had lost its alt text

Pushing a page to Instatic wipes every node-level attribute patch on it, and the 33-page sync was not followed by the restore step. 549 images across the site carried an empty alt, including all 111 on the smile gallery.

Restored from the local build as the source of truth. The five on the home page that had never been written are now described too.

Fixed44 URLs

The blog shipped a menu button with no menu

The post template pulled the mobile drawer out of another page into a variable and never inserted it; the blog index never had one at all. So all 43 posts and the index served a burger whose aria-controls pointed at nothing, and drawer.querySelectorAll threw — taking the Escape handler and both layout-refresh calls down with it.

Fixedevery page, phone widths only

Nine links of the mobile menu were unreachable

The drawer is a column that centres its content and scrolls. At 390×844 the content is 946px tall in an 844px box, so centring pushed the overflow off the top, where scrollTop cannot follow: the first nine entries of the site map sat at −166px on every page, and the drawer still reported itself open.

Only the mobile pass could see this. The drawer, the burger and the touch behaviour of the sliders exist at phone widths and nowhere else.

Fixed1 page, phone widths only

The thank-you page scrolled sideways

A parallax attribute sat on a <figure> instead of the image inside it. The effect scales its target by 1.12: on the image, clipped by the figure; on the figure, it scales the clipping container. 21px either side against a 17px gutter, and the page carried 4px of horizontal scroll.

Stop-gapall 77 URLs

Every URL published the same title and description

Instatic renders the site title and description into every page's head. The per-page title is stored correctly and simply never emitted, and the platform exposes no way to write head tags. There were no canonical links anywhere either, and the 43 blog posts had no structured data at all.

One head script now carries all 77 routes: title, description, self-referential canonical, Open Graph, and Article markup for the posts. Google renders this. Facebook and LinkedIn do not, which is why the durable fix is still server-side in the Instatic deployment.

Why every gate was green

The site exists three times over, and the checks only covered two of them.

The build tests read the local package. The parity check compares node counts on the Instatic draft, which a CSS override cannot change. The simulator replayed the real imported markup, but against two of the three stylesheets the platform actually serves — and the missing one was exactly where the rule that killed the sliders lived. Nothing had ever driven the published page.

So the answer to “is the size of the site causing the errors?” is no. 77 URLs is a perfectly ordinary size. The problem was that the layer the client looks at was the one layer nobody measured, so defects survived every green result. That gap is now a gate of its own, run at both widths, and the simulator loads all three stylesheets.
