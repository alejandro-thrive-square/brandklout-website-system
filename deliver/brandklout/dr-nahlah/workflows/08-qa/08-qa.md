# Workflow: 08 - QA

## Client-Facing Overview
Before launch, we test the staged site across devices, links, forms, SEO basics, performance, and visual accuracy.

> [!IMPORTANT]
> **Integrity Rule**: Any change to the Python executor or technical logic of this workflow must be documented here immediately.

## Operational Purpose
Verify the staged delivery build against quality standards: pixel fidelity, CMS/content structure, responsiveness, functionality, SEO readiness, accessibility, and performance. The QA surface changes by offer: full Webflow builds require full-site QA, migrations verify the outputs of `12`, `13`, and `14`, improvement work verifies the scoped plan from `15`, and AI Vercel/Airtable builds verify the code package and runtime content routes from `17`.

## Inputs From Sales / Previous Phase
- Staging or preview URL and build manifest.
- Approved design reference screenshots and final content.
- Known critical user paths, forms, analytics, and integration requirements.

## Execution Steps
1. Compare staging templates against approved designs across breakpoints.
2. Crawl pages for SEO, metadata, headings, links, schema, and alt text.
3. Test forms, CTAs, navigation, CMS edge cases, analytics, and responsive behavior.
4. Triage defects, then block launch until critical/high issues are resolved.

## Offer-Specific Adaptations
- **Development from Scratch**: Run full-site QA across design fidelity, content, CMS, responsiveness, forms, SEO, performance, accessibility, and launch readiness.
- **Figma to Webflow**: Prioritize visual fidelity against the approved Figma file, responsive behavior, CMS templates, interactions, forms, and SEO basics.
- **Migration to Webflow**: Verify migrated content against `13-content-export-import` and redirects/metadata against `14-migration-seo-redirects`.
- **Webflow Improvements & Updates**: Scope QA to the changed pages/components and regression surface defined in `15-improvement-intake-audit`.
- **AI Site with Claude, Vercel & Airtable**: QA the Vercel preview/site package from `17-ai-site-build-airtable`, including Airtable route behavior, secret boundary checks, loading/empty/error states, motion, responsive behavior, and the scoped SEO rendering expectation.

## Performance budget gate — `perf-budget.mjs`

Run against the **published** URLs after every publish, alongside the site test and
the GSAP interaction test. It exists because a performance regression on this site
was invisible until somebody happened to open PageSpeed.

```bash
node perf-budget.mjs                                   # 5 representative pages
node perf-budget.mjs --all --json .tmp/perf-after.json # all 13
node perf-budget.mjs --base https://encorercm.com      # the origin, not the domain
```

It asserts **causes, not a score** — the score drifts with network conditions and
Lighthouse versions, the causes do not. Each check encodes a way this site has
actually broken:

| Check | The failure it catches |
|---|---|
| no render-blocking JS in `<head>` | Instatic emits classic scripts with no `defer`/`async`, and ignores `timing` at publish |
| blocking CSS ≤ 20 KB gz | the one budget that has always passed; it is here so a regression is caught |
| above-the-fold images are not lazy | `base.image` defaults `loading` to `lazy`, so the LCP image shipped lazy |
| exactly one `fetchpriority="high"` | zero means no LCP hint; two means they compete |
| no duplicate `alt` attributes | `htmlAttributes.alt` renders before the library's alt, and HTML keeps the first |
| every image has alt text | reads the RENDERED attribute, not the prop — see the gotcha below |
| third-party iframes are lazy | a snippet embed ignores its own `lazy` prop |
| no parser-blocking third-party scripts | vendors paste `<script src>` with no `defer` |
| media ≤ 2 MB | a 9.2 MB hero video |

**Waivers are decisions, not passes.** `BUDGET.mediaWaivers` and
`BUDGET.eagerIframeWaivers` each carry a reason string and a date. Anything waived
still prints; nothing is silently skipped.

### Two gotchas this gate has already earned

- **Measure the rendered attribute, not the prop.** A prior pass checked
  `htmlAttributes.alt != null`, found a value, and reported 13 YouTube thumbnails as
  covered. The value was the **empty string**. Reading the published HTML is what
  caught it.
- **Node's `fetch` decompresses transparently**, and this origin serves chunked with
  no `content-length`, so both the header and the buffer length give the
  *decompressed* size. The gate's first run reported 114,222 B of CSS as "gzip". It
  now gzips locally with `zlib` instead of trusting the response.

### Not covered here

`perf-budget.mjs` does not measure LCP, TBT or CLS — it has no browser. For those,
run a real PageSpeed pass and file the report with the publish. The CDP harness in
`.tmp/cdp.mjs` is the place to add real metrics if that becomes worth it.
