# v2 redesign — the Figma system, rebuilt

**2026-08-28.** The site that went live on Instatic on 2026-08-27 was built from the pre-takedown
WordPress screenshots, deliberately, to get 71 pages back up the same day. This pass replaces its
design with the client-approved Figma system and rebuilds the layout on top of it.

  (the current task) and [Build Home Page](https://app.asana.com/1/1210572425689866/project/1217162291525925/task/1215184684664966)
  (carries the brand guide PDF and the client's own photo album).

  **Final** (frame `1940w expanded`, the chosen direction) and page **Handoff Documentation**

The brief was: **keep the Figma's colours and typography, improve the layout.** That is what this
does. Every hex and every type size below is verbatim from the handoff frames; the arrangement is
not a tracing of the comps.

### Type (`Handoff — Typography`)

Three families, exactly as specified: **Newsreader** (editorial headings), **Nunito Sans** (body),
**Karla** (UI labels and navigation). All three are on Google Fonts, so nothing here repeats the
Adobe Typekit licence problem that killed "stolzl" in v1.

| Role | Figma spec |
| :--- | :--- |
| Hero headline | Newsreader Light · 52 / 58.24 |
| Page headline (H2) | Newsreader Light · 38 / 43.2 |
| Section headline | Newsreader Regular · 42 / 46.2 |
| Doctor names | Newsreader Regular · 24 / 28.8 |
| FAQ questions | Newsreader Regular · 20 / 26 |
| Step numerals | Newsreader Regular · 28 |
| Body large / standard / card | Nunito Sans Regular · 21 / 17 / 15 |
| Nav & labels / utility / micro / tags | Karla Medium · 15 / 13 / 11 / 12 |

`theme/site.css` expresses these as `clamp()` so they hold at 1920 **and** read at 1280. The
Figma's 52px hero at a 1440 viewport would be oversized for the measure it sits in.

**One deliberate departure: no UI label is set below 12px.** The handoff specifies Karla Medium at
11px for micro labels and 12px for tags, and `responsive.mjs` flags every text node under 12px on
every page — correctly. Uppercase at `.2em` tracking is the hardest setting there is to read small,
and the patients in this practice's own hero photograph include the grandparents. Every Karla label
is floored at `.75rem`. It is a visible change from the comps and it is on purpose.

### Layout (`Handoff — Layout & Spacing`)

Page 1920 wide, content area 1744, **88px side gutters**, sections ~95px top / 97px bottom, all
card outlines and section dividers `1px #E2D5C5`. Gutters and section rhythm are kept as-is
(`--gutter: clamp(1.25rem, 4.6vw, 5.5rem)` lands on 88px at 1920). The 1744px content width is
**not** kept for text: 1744px of 17px body copy is a ~200-character measure. Containers are
1600 / 1360 / 1040 / 760, and grids use the widest.

## What was changed, and why

The comps compose the page as thirteen full-width bands of equal weight, each holding a grid of
equal cards. That is the exact failure mode named in
[`deliver/brandklout/docs/DESIGN-STANDARD.md`](../../../docs/DESIGN-STANDARD.md) — swap any two
sections and nothing breaks, because nothing was ever connected. Nine changes:

1. **Hero.** Comps: symmetrical 50/50 split, photo in a box. Now: asymmetric split, the photograph
   bleeding to the right edge, an "appointments" plate overlapping its corner, and a **fact strip**
   under the buttons — the three things a first-time visitor actually wants (adults *and* kids,
   board-certified paediatrics, 0% financing) instead of finding them four sections down.
2. **Credential bar.** Kept on the dark ground, because the five badge files the practice published
   are white artwork on transparency and only exist for a dark ground. What is added is the label
   *Credentialed by* and a forced uniform logo height — five unexplained marks at five different
   intrinsic sizes told a visitor nothing.
3. **Value props.** Comps: two bordered cards, heading over body over image. Now: photograph first
   with the audience tag hung on it (copper for adults, sage for kids, per the palette's own note),
   so the split between adult and child care is legible before a word is read.
4. **Service index.** Comps: fourteen identical bordered tiles in one 4-column grid. Fourteen equal
   boxes rank nothing, so a visitor must read every label to find theirs. Now **three labelled
   groups** — Everyday care / Cosmetic and orthodontic / Restorative and surgical — with hairlines
   instead of boxes, an icon, and one line of plain English per treatment.
5. **Icons.** Comps: 14 icons pulled from six different libraries (`phosphor`, `game-icons`,
   `material-symbols-light`, `vaadin`, `streamline-ultimate`, `hugeicons`, plus one custom). Six
   libraries is six licences and six drawing grammars. `site/icons.mjs` draws all sixteen once to
   one grammar — 24-unit box, 1.6 stroke, round caps — inline, in `currentColor`, so the copper
   lives in the stylesheet. No requests, crisp at any size, survives the Instatic import.
6. **Reviews.** Comps: *"Google reviews screenshot with scroll indicators."* A screenshot cannot be
   read by a screen reader, does not reflow on a phone, and is wrong the day the rating moves. The
   same information is rebuilt as markup from the practice's own published reviews.
7. **FAQ.** Two columns with the heading sticky beside the accordion, `<details>` so it works with
   JavaScript off.
8. **Footer.** Comps' four columns adopted (brand / Care / Patients / Hours). The v1 footer ran
   "Useful Links" beside "Menu", which repeated four destinations twice, and a separate tan
   "Contact Us / Office Hours" band above it that repeated the footer again. Both are gone.
9. **Closing CTA.** Every inner page now ends on the credential strip plus a booking block, so no
   page dead-ends. Previously the article renderer stopped at the article.

## What did NOT come across from the comps, and why

| Comp says | Shipped | Why |
| :--- | :--- | :--- |
| Eyebrow "KATY, TEXAS · SINCE 1997" | "KATY, TEXAS" | **Nothing in the practice's own published copy supports a 1997 founding date.** Needs the client to confirm before it goes back. |
| Reviews block "4.9 \| Top Rated Service" | Review quotes, no numeric rating | Same reason. A star average printed as static text is a claim, and it is wrong the moment it moves. `reviewLockup()` is in the component library ready for a confirmed figure. |
| Four homepage FAQs (insurance / age / booking / weekends) | Four the practice has already answered | The comps name four questions and carry **no answers**. Rather than invent them, the homepage runs four real Q&A pairs verbatim from `/faq-page/`. **The comps' four are better questions — get answers from the practice and swap them in.** |
| Nav: ADULTS / KIDS / COSMETIC / ABOUT / PATIENTS | The real six-item menu | Those five labels do not reach the 71 pages this site actually has. The information architecture stays the live site's; only the styling is new. |

## Gates

Still enforced, run in this order and **never concurrently** — `build.mjs` deletes and rewrites
`dist/` underneath whatever is serving it:

```bash
node build.mjs && node audit.mjs && node responsive.mjs
```

> [!WARNING]
> **`responsive.mjs` carries a hard-coded token value as its readiness sentinel.** It waited for
> `--accent` to equal `#00bde0` — a v1 colour this retheme deleted — so after the retheme it
> reported **all 71 pages at all 3 widths as "page never finished loading"**, which reads exactly
> like a site-wide layout collapse and is not one. It now checks `--brand` = `#8c6349`, with a
> comment saying to change it whenever the stylesheet's variables are renamed. This is the third
> time this gate has lied; the runbook's standing advice holds — **if it ever reports a whole-site
> failure, suspect the gate first.**
