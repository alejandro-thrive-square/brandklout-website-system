# 2026-09-25 — Share images that previews actually show: 1200x630, under 300 KB, with size tags

The client, after the Open Graph work: "It seems like production is not applied the correct way
because it's not displaying the Open Graph".

## What was wrong

The tags were right, and every crawler got them. Checked as facebookexternalhit, Twitterbot,
LinkedInBot, Slackbot and WhatsApp, on www and on the bare domain: 200, tags at byte ~4.5k. The
**images** were the problem:

- Service pages and articles shared their hero, a **1536x2046 portrait of 350-613 KB**. WhatsApp
  drops a preview image over ~300 KB, and Facebook/LinkedIn/X crop to 1.91:1, which cut the
  portrait through the middle.
- There were **no `og:image:width`/`height` tags**, so Facebook shows a link's first share with no
  picture while it fetches the image.
- Previews shared before today stay cached by each network until re-scraped.

## What changed

- `og/collect-share-sources.mjs` reads what each page shares from the live HTML (247 on production,
  223 on staging; 57 distinct images).
- `og/render-share-cards.mjs` renders a 1200x630 version of each in Chrome, JPEG q80, 36-139 KB:
  - wide photos (>= 1.6:1) are cover-cropped;
  - anything taller is shown **whole**, centred on a blurred, darkened copy of itself, so no face
    is cut.
- `bugherd/set-share-images.mjs` uploads the share images and points every page's and article's
  override `image` at its share version. Descriptions are kept.
- **open-graph 1.2.3** emits `og:image:width`, `og:image:height` and `og:image:type` when the file
  name carries the size (`…-1200x630.jpg`, the way the media library names uploads). Installed on
  both instances.
- `set-open-graph.mjs` no longer replaces an image that is already set, so a re-run cannot put the
  heavy originals back.
- `check-open-graph.mjs` now also requires 1200x630 with size tags and under 300 KB.
  Production 253 URLs, staging 223 URLs, 0 problems.

## For the client

Links shared before today keep their old cached card. Re-scrape each one once:

- Facebook: developers.facebook.com/tools/debug, then "Scrape Again".
- LinkedIn: linkedin.com/post-inspector.
- X refreshes on its own within about a week.

## Gotchas

- **A new page gets no share version automatically.** Re-run the three steps above after adding
  pages or changing a hero.
- The share file names keep the source's name, so a re-cut source needs a new file name (see the
  memory note on the media library skipping uploads by basename).
