Install the Embed capability on an Instatic client site, or verify it still works.

Before running:
- Confirm which site this is for, and put it in the repo-root .env as INSTATIC_BASE_URL
  (with INSTATIC_EMAIL and INSTATIC_PASSWORD). The toolkit refuses to guess: a shared
  installer that inherited another client's default would publish to the wrong site.
- Confirm the client actually wants third-party embeds. Installing the plugin with strict
  mode and empty settings changes nothing, but the default is compatible mode, which opens
  the pages carrying an embed to anything over https. That is a decision, not a default to
  inherit silently.
- Confirm nobody is mid-edit in the Instatic admin. Installing needs step-up auth, which
  rotates the session cookie.

Read 18-instatic-embeds.md first, in particular the two policy modes and the publish
warning: on Instatic a publish bakes EVERY page, so a stale draft anywhere on the site
ships with whatever you were publishing. Audit one known page before and after.

Order that wastes the least time:
1. node test-embed-origins.mjs && node test-embed-module.mjs      (offline, no site)
2. node pack-plugin.mjs embed-origins .tmp/embed-origins.zip
3. node install-plugin.mjs .tmp/embed-origins.zip                 (dry run: read the grants)
4. node install-plugin.mjs .tmp/embed-origins.zip --apply
5. node verify-embed-editor.mjs --place && --check && --cleanup   (publishes nothing)
6. node verify-embed-scripts.mjs --place && --check && --cleanup  (this one publishes)

When a widget loads and renders nothing, do not assume the platform. Reproduce it on a
bare localhost page with no CSP (probe-elfsight-bare.mjs) before spending time on the
site, and confirm in a real browser rather than headless.
