The Embed Block

Put a third-party widget on a page yourself: a booking form, a review wall, a map, a video player. Paste a URL or the vendor's snippet, publish, done. No developer, no code asset, no ticket.

Paste it and publish. That is the whole job.

An iframe, a script, or a whole snippet with both — paste what the vendor sent you and publish. The site works out what that page needs and allows exactly that, on that page, when it publishes. There is no form to fill in first and nobody to ask.

Anyone editing a page

Place the Embed block. Insert it, paste the vendor's URL or snippet, choose how tall it should be, publish. What you pasted is what that page is allowed to load — and only that page.

Operator, once per site

Decide how open the pages with embeds are. This site is set to Compatible: a page that carries an embed may load whatever that widget needs. Switching it to Strict tightens that, at the cost of some widgets needing an address added by hand.

Worth knowing the shape of it: only the pages that actually carry an embed are opened up, and only to load things over https. Every other page on the site keeps the original locked-down policy, untouched. A widget on the contact page changes nothing about the home page.

Placing one

  1. Open the page and add the block

    In the editor, click the + on the canvas (or Insert module in the Layers panel), then pick Embed. It sits under Media, next to Image and Video.

  2. Tell it where the widget lives

    The block lands with a grey note reading “Embed — paste a URL in the properties panel”. That is correct, not broken. In Properties on the right, set Source:

    URL — paste the address the vendor gave you. This is the right choice almost every time.

    HTML snippet — paste the vendor's markup exactly as they sent it, for the cases the URL form cannot express.

  3. Choose how tall it is

    Auto lets the widget report its own height, so it stays right on a phone and on a desktop without you guessing. Use it unless the widget refuses to cooperate.

    Fixed pins it to a number of pixels. Aspect ratio keeps a shape (16:9 for video, 1:1 for a square feed) and scales the height with the width.

  4. Scripts: paste them too

    Plenty of vendors send a snippet that is an iframe and a line of script, or just script. Paste the whole thing into HTML snippet. Both kinds work: a script hosted by the vendor, and a script written inline in the snippet.

    Paste it exactly as the vendor sent it. You do not need to understand any of it, and you do not need to tidy it up — inline handlers, init calls, several script tags at once, all of it runs.

  5. Publish, then look at the live page

    The approval list is applied while the site publishes, so a newly approved vendor reaches the live site on the next publish and not a moment before. Open the real page afterwards and confirm the widget is there.

What you will see, and what it means

The block shows grey placeholder text on the canvas
It has no URL or snippet yet. Fill in Source and the address in the Properties panel.
It says the snippet contains a script, and shows nothing
Expected. Scripts never run inside the editor canvas, only on the published page. Publish and look at the real page to see it.
The widget is blank on the live page
First check you published after adding it — the page a visitor sees is the last published one. If it is published and still blank, open the browser console on that page: a refusal names the exact address that was turned away, which is often not the company's marketing domain. Paste that address into Allowed iframe origins under Plugins → Embed Origins and publish again.
The widget loads but shows nothing
Check the browser console on the live page. If nothing was refused, the widget is loading fine and the emptiness is the vendor's — most often an app configured for a different website or account. If something was refused, tell whoever maintains the site: the page should be allowing it.
The widget appears, but it is the wrong height
Some widgets do not report their own size. Switch Height from Auto to Fixed and set a number, or to Aspect ratio if it should keep a shape.
You changed a setting and nothing happened
Settings apply at publish time, to pages published after the change. Publish the site.

The one thing to be careful about

A script is not a frame

A widget inside a frame is sealed off: it cannot touch the page around it, its cookies, or anything a visitor types elsewhere. A script you paste is not — it runs as part of the page, with the same reach as the site's own code. That is true on any platform, Webflow included, and it is the reason to paste snippets from companies you actually deal with rather than ones you found.

The difference here is scope. A page with an embed on it accepts scripts; a page without one does not, and most of this site does not. So the question to ask before pasting is the only one that was ever load-bearing: do we actually deal with this company? A snippet from the client's own booking system is not the same as one found in a forum.

Worth knowing before anyone asks for it: plenty of vendors send a script that is pure convenience. The live review widget on this site never loads its vendor's script at all — the site sizes the frame itself — and it works perfectly.

Before any publish of this site

Publishing rebuilds every page, not just the one you edited, so any page whose draft has drifted from what is live ships with your change. If you are publishing after a gap, check the home page afterwards as well as your own.

How we know this works

Three automated checks run against the real site, each covering a path the others cannot see. One drives a published page and confirms the widget loads, sizes itself and is not refused. One drives the admin editor and confirms a person is offered the block, can place it, and gets every field listed above. The third pastes a real vendor snippet — an iframe, the vendor's own script and an inline script together — publishes it, and confirms that both scripts actually ran on the live page, because a script that was refused still looks perfectly fine sitting in the page.
