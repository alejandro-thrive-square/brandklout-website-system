### Phase 1: Style Direction

1. Read the project overview at deliver/[CLIENT_NAME]/docs/project-overview.md. Extract: industry, audience, brand personality, positioning, existing brand assets.

2. Read approved wireframes from deliver/[CLIENT_NAME]/workflows/02-wireframe/.tmp/final-wireframes/. Note: page count, page types, section structure per page, content hierarchy.

3. Read graphic resources from deliver/[CLIENT_NAME]/workflows/03-graphic-resources/.tmp/. Note: logos, brand colors, fonts, imagery style, any mood board or style references.

4. Open the initialized selected design-system package in deliver/[CLIENT_NAME]/workflows/00-client-delivery-initialization/.tmp/design-system/.
   - modern-saas: SaaS, developer tools, fintech
   - corporate: Enterprise, consulting, professional services
   - creative-agency: Creative studios, agencies, portfolio brands
   - minimal-portfolio: Designers, photographers, personal brands
   - bold-startup: Startups, consumer apps, modern brands
   - luxury: High-end brands, fashion, premium products

5. Read the matching token file from library/foundations/tokens/ as a starting point.

6. If the client brief strongly matches a known brand style, read the corresponding file in library/design-systems/ for deeper philosophy guidance.

7. Create a custom token JSON by merging:
   - Base token structure from the selected style
   - Client's actual brand colors (replace primary/secondary/accent)
   - Client's fonts (replace font-primary/font-secondary)
   - Adjust spacing/radius/shadows to match the client's brand personality

8. Write outputs:
   - deliver/[CLIENT_NAME]/workflows/04-design/.tmp/style-direction.md (rationale, selected style, references used, deviations from base)
   - deliver/[CLIENT_NAME]/workflows/04-design/.tmp/design-tokens.json (custom token set)

### Phase 2: HTML/CSS/JS Prototype Generation

9. For each page from the wireframes, compose a prototype HTML file:

   a. Open library/sections/SECTION_INDEX.md. For each section in the wireframe, find the closest matching section pattern.

   b. Read the matching section HTML files from library/sections/.

   c. Assemble sections into a complete page:
      - Apply the custom design-tokens.json as CSS custom properties in the <style> block
      - Replace placeholder content with client content (from wireframes/project overview)
      - Replace placeholder images with client images (from graphic resources) or appropriate picsum.photos URLs
      - Integrate client logo and brand elements
      - Ensure all sections flow together cohesively

   d. Add animations:
      - Open library/animations/ANIMATION_INDEX.md
      - Select appropriate animation modules for the style direction
      - Include CDN dependencies (GSAP, ScrollTrigger, Lottie as needed)
      - Add data attributes to elements: data-reveal, data-text-split, data-parallax, etc.
      - Include the animation JS inline or reference from library/animations/

   e. Ensure responsive design:
      - Test at 1440px, 1024px, 768px, 375px breakpoints
      - Adjust grid layouts, font sizes, spacing, and visibility per breakpoint
      - Mobile navigation pattern (hamburger menu)

   f. Each prototype must be a self-contained HTML file (inline <style> and <script>).

10. Create a prototype manifest:
    ```json
    {
      "client": "[CLIENT_NAME]",
      "style_base": "modern-saas",
      "pages": [
        {
          "file": "home.html",
          "wireframe_ref": "wireframe-home.pdf",
          "sections": ["hero-split-image", "features-bento-grid", "testimonials-carousel", "cta-full-width-gradient", "footer-mega-columns"],
          "animations": ["scroll-reveal-gsap", "counter-animation"],
          "breakpoints": ["1440", "1024", "768", "375"]
        }
      ]
    }
    ```

11. Write outputs:
    - deliver/[CLIENT_NAME]/workflows/04-design/.tmp/prototypes/*.html
    - deliver/[CLIENT_NAME]/workflows/04-design/.tmp/prototype-manifest.json
