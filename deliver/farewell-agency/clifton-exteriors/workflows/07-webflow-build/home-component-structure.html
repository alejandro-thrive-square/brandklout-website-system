Architecture Patterns

  • All content edits go through section-instance props — pages contain no raw content elements.
  • Prop forwarding: section props bind into nested atoms via {sourceType:"prop", propId} bindings.
  • Variant IDs as prop values: style props store IDs ("base" or a UUID), not names — look them up with includeVariants before setting.
  • Links by page ID ({mode:"page", to:{pageId}}), images by asset ID.
  • JS behaviors ride on data attributes (marquee, review wall) with logic in HTML embeds / global code.

In Depth: Components Inside Components

Every section definition nests further component instances. That creates a three-layer content model — and only the top layer is per-page: 

Layer 1 — PAGE INSTANCE props     per page   the only per-page layer
Layer 2 — DEFINITION internals    shared     elements + nested instances, same on every page
Layer 3 — NESTED INSTANCE props   shared     forwarded (bound to Layer 1) or hardcoded
  • Per-page content must arrive via an unbroken forwarding chain ({sourceType:"prop", propId}) from Layer 1. Anything page-specific sitting at Layer 2/3 is a bug — or a deliberately page-specific duplicate component.
  • Editing a definition (Layer 2/3) hits every instance on every page — check instanceCount before touching it. Layer 1 edits affect one page only.
  • Example: USP's nested Row / Heading for Section forwards 7 of 8 props from USP's own props; the 8th is hardcoded in the definition.

Proven Failure Mode: Clone Leftovers (gutters, 2026-07-12)

Duplicating a component (FAQ Windows → FAQ Gutters/Siding/Insurance) copies the whole Layer-2 tree. Updating the name + Layer-1 props makes the page look done while source-page content still renders from inside the definition:

  • FAQ Gutters: 2 windows Q&A were rendering live on /gutters (6 hardcoded items; old site + paste artifact confirm 4) — deleted, verified 4 remain.
  • Gutters Layer-1 misses: 4 alt-text props still said "Bedroom windows" / "Tall windows" — fixed.
  • FAQ Siding: same leftovers but visibility:false — renders fine, clutter remains.
  • FAQ Insurance: still carries the windows Q&A — open item (visibility unverified).
  • FAQ Roofing: clean.

Audit recipe: ① page tree depth 3 → scan instance props; ② per section, get_all_elements with scope_component_id + depth:-1 (batched, grep the saved output offline for source-page terms); ③ check visibility on hits; ④ confirm intent vs old-site inventory / paste artifacts before deleting from a definition.
