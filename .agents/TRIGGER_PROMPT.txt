TRIGGER PHRASE: @dispatch

When a message contains a line starting with @dispatch, execute the cross-
provider dispatch workflow below. This routes the task to another provider's
agent (Claude / Codex / Pi) and returns its answer. Works on Windows (local)
and the Hostinger VPS identically.

SYNTAX
  @dispatch [async] [diff:N] [account:team|personal] <role|agent> <task...>

  async      optional. If present, queue via handoff (background worker).
             Default is synchronous: run now and return the answer.
  diff:N     difficulty 1-10. Routes to a capability tier that sets the model
             AND reasoning effort (see CAPABILITY). If omitted, YOU assess it
             per DIFFICULTY SELF-ASSESSMENT and add diff:N.
  account:X  optional. Claude account: team (default ~/.claude) or personal
             (~/.claude-account-b, Max plan). Only affects claude agents.
             Shorthand: roles design2/build2/docs2 also use the personal account.
  role       a routing keyword from the table below, OR a named agent
             (e.g. codex-backend, pi-audit, claude-design).
  task       free text - the full instruction for the sub-agent.

ROUTING (role -> default agent / provider)
  backend | automation           -> codex-backend   (Codex / gpt-5.5)
  docs | token-opt | linking     -> claude-docs     (Claude / Sonnet)
  audit | system-improvement     -> pi-audit        (Pi / GLM)
  design | build                 -> claude-design   (Claude / Fable)
  design2 | build2               -> claude2-design  (Claude #2 / Fable)
  docs2 | token-opt2 | linking2  -> claude2-docs    (Claude #2 / Sonnet)

CAPABILITY (diff:N -> tier -> model / effort)   [opt-in]
  1-3  lite       Claude Haiku   | Codex gpt-5.5 (reasoning low)
  4-6  standard   Claude Sonnet  | Codex gpt-5.5 (reasoning medium)
  7-9  heavy      Claude Fable   | Codex gpt-5.5 (reasoning high)
  10   max        Claude Opus    | Codex gpt-5.5 (reasoning high)
  Difficulty biases cost/latency: easy tasks -> cheap model, hard tasks ->
  frontier. When unsure, round UP (under-routing a hard task risks a wrong
  answer).

DIFFICULTY SELF-ASSESSMENT (the calling agent rates the task)
If a trigger line has no diff:N, YOU rate the task 1-10 first, state the rating
in one short phrase, then dispatch with diff:N. Calibrate:
  1-3 lite      trivial/mechanical: formatting, a docstring, a tiny regex,
                renaming, "explain X".
  4-6 standard  normal feature work: a small endpoint, a component, a doc
                section, a routine audit. MOST tasks land here.
  7-9 heavy     multi-step design/architecture: a design system, a retry queue,
                cross-file refactor, novel integration.
  10   max      frontier one-shot: open-ended architecture, large system design,
                high-stakes.
Bias UP when unsure (under-rating a hard task risks a wrong answer). If you
genuinely cannot tell, omit diff:N (uses the agent's default model).

HOW TO RUN (from the repo root)
  Sync (get the answer now):
    python .agents/dispatch.py ask \
      --role <role> [--diff N] [--account team|personal] \
      --cwd "<active workflow folder>" \
      --prompt "<task>"

  Async (queue, then collect later):
    TID=$(python .agents/dispatch.py handoff \
      --role <role> [--diff N] [--account team|personal] \
      --cwd "<active workflow folder>" --prompt "<task>")
    # a worker (local, or the VPS systemd timer) processes it
    python .agents/dispatch.py collect "$TID"

  (On the VPS, use `python3` instead of `python`.)

RULES
  - Set --cwd to the active workflow folder so the sub-agent reads the right
    directive and is bound by that folder's mcp-access.md. If no workflow folder
    applies, use the repo root.
  - Return the sub-agent's answer to the user (sync). For async, return the task
    id and say it will be processed by a worker; offer to collect when ready.
  - Mutating actions (publish/delete/deploy/email/billing/access changes) still
    require explicit confirmation - dispatch does not bypass that.
  - If a provider CLI is missing, run: python .agents/dispatch.py doctor

EXAMPLES
  @dispatch backend write a Flask webhook that proxies Webflow form submissions
  @dispatch backend diff:2 add a docstring to this function
  @dispatch backend diff:9 design the schema + retry queue for our billing webhooks
  @dispatch docs reduce README.md token count by 50% while keeping the meaning
  @dispatch design diff:8 draft a hero section for a luxury real-estate landing page
  @dispatch design diff:10 architect the full design system + component library
  @dispatch docs account:personal draft a personal note (runs on your Max account)
  @dispatch design account:personal diff:8 prototype a side-project landing page
  @dispatch audit review .agents/dispatch.py for security issues
  @dispatch async backend diff:9 build the full Stripe webhook + retry queue (large task)
